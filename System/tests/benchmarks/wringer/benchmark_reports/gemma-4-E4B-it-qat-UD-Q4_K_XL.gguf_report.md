)

**How it works:** DeepSpeed manages memory by only keeping what is absolutely necessary for the current computation on the active device, offloading the rest.

*   **8-bit Quantization ($\text{INT8}$):** Reduces model size by $\approx 4\times$ compared to $\text{FP32}$. Offers a significant VRAM reduction with minimal performance degradation.
*   **4-bit Quantization ($\text{INT4}$ / NF4 / GPTQ):** Reduces model size by $\approx 8\times$ compared to $\text{FP32}$. Achieves the highest memory savings but can involve a more noticeable drop in accuracy, requiring careful tuning.
*   **Mixed Precision:** Using lower precision (e.g., $\text{FP16}$ or $\text{BF16}$) for computations while keeping critical parameters in higher precision. This halves the memory usage compared to $\text{FP32}$.

### 2. Optimizing Inference Techniques (Reducing Runtime Overhead)
These methods change *how* the model is run to reduce the memory needed for activations and intermediate states.

*   **Gradient Checkpointing (Activation Checkpointing):** During the forward pass, instead of storing every intermediate activation (which consumes massive VRAM), it only stores a few checkpoints. During the backward pass, it **re-computes** the necessary intermediate activations on the fly.

    *   **FlashAttention:** Reorders the attention computation to minimize the amount of data moved between the GPU's High Bandwidth Memory (HBM/VRAM) and slower on-chip SRAM. This is crucial for efficiency.

### 3. Architectural Adjustments (Reducing Model Footprint)
These techniques modify the model structure itself, which requires retraining or using pre-optimized variants.

*   **Pruning:** Removing redundant weights (connections) from the network that contribute little to the output. This creates a sparser, smaller model.
    *   **Challenge:** Requires specialized hardware/software to utilize the sparsity efficiently and often requires fine-tuning.
*   **Knowledge Distillation:** Training a smaller, faster "student" model to mimic the behavior of a much larger, high-performing "teacher" model. This allows you to use a smaller model while retaining most of the performance.

3. **Avoid Dynamic Data Structures:** Where possible, use fixed-size arrays instead of dynamic lists or maps.
4. **Optimize Loops:** Profile loops aggressively; reduce internal iterations and cache misses.
5. **Batch Operations:** Group small, frequent I/O or network calls into larger, less frequent batches.
6. **Cache Locality First:** Structure data in contiguous memory blocks to maximize CPU cache hit rates.
7. **Minimize Function Calls:** Reduce the overhead associated with function call setup and teardown where performance is critical.

11. **Early Exit Logic:** Implement guard clauses and early returns to avoid unnecessary processing in failing or trivial cases.
12. **Avoid Recursion (Prefer Iteration):** Limit deep recursion to prevent stack overflow and leverage iterative performance.
13. **Pre-Calculate Constants:** Compute mathematical constants or frequently used values once and reuse the result.
14. **Prefer Bitwise over Arithmetic:** Replace division, modulo, and multiplication with bit shifts and masking where applicable.

19. **Memory Alignment:** Ensure data structures are aligned to optimal memory boundaries for faster CPU access.

22. **Minimize Global State Access:** Reduce contention and overhead associated with accessing heavily shared global variables.
